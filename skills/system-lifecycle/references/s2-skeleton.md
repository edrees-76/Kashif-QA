# S2 — الهيكل العظمي (Phase 0)

الهدف: نظام "يمشي" من طرف إلى طرف بلا ميزات — يبني، يفتح، يتصل بقاعدة
البيانات، يسجّل الأخطاء. السبب: مشاكل البيئة والبنية تظهر هنا رخيصة، لا في
منتصف Phase 3 مختلطة بمنطق العمل.

## قائمة Phase 0 (تُكيَّف حسب المنصة المختارة في architecture.md)

1. **المستودع:** إنشاء repo على GitHub، `.gitignore` مناسب للمنصة، فرع
   `main` محمي من الدفع المباشر، وفرع عمل لكل Phase (`phase-1-...`).
2. **ملفات التوثيق في الجذر:** `docs/requirements.md`، `docs/architecture.md`،
   `docs/tasks.md`، `PROJECT_STATE.md`، `README.md`، `CHANGELOG.md`،
   ومجلد `docs/adr/` لسجل القرارات.
3. **هيكل الحل:** الطبقات كما في architecture.md (مثلًا UI / Core /
   Data / Tests). مشروع اختبارات فارغ منذ اليوم الأول.
4. **قاعدة البيانات:** أول migration بجدول واحد على الأقل + جدول
   AuditLog إن كان مطلوبًا في المواصفة.
5. **الإعدادات:** ملف إعدادات للبيئة، وبيانات اختبار (seed) منفصلة تمامًا
   عن أي بيانات إنتاج.
6. **التسجيل والأخطاء:** logging إلى ملف + معالج أخطاء عام يمنع الانهيار
   الصامت.
7. **نافذة/صفحة رئيسية فارغة** تثبت أن السلسلة كلها تعمل.
8. **رقم إصدار** `0.1.0` ظاهر في الواجهة.

## اختيار المنفّذ والتسليم

حدّد أداة التنفيذ هنا (إن لم تُحدَّد) وسجّلها في `PROJECT_STATE.md`.
اقرأ ملمحها من `references/executors.md`، ثم استخدم
`assets/executor-prompt.template.md`. إن كانت الأداة تدعم ملف تعليمات
دائم للمشروع (مثل `CLAUDE.md` في Claude Code أو قواعد Antigravity)،
أنشئه ضمن Phase 0 وضع فيه القيود الثابتة. Phase 0 برومبت واحد أو
اثنان على الأكثر.
